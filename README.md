# 剪贴板分组粘贴（ClipChunkPaste）

Windows 托盘小工具：**Ctrl+V 时把剪贴板文本按每 20 个字符一组，自动逐组依次粘贴**，用来对付「单次粘贴上限 20 字」的输入框，免去手动一段段复制粘贴。

## 文件说明

| 文件 | 作用 |
| --- | --- |
| `clip_chunk_paste.py` | 主程序（单文件，纯 ctypes 调 Win32 + pystray 托盘） |
| `启动.bat` | 双击启动，无控制台窗口 |
| `调试启动.bat` | 双击启动并保留控制台，出错时能看到原因（排查用） |
| `安装依赖.bat` | 重建 `.venv` 并安装 pystray / pillow |
| `打包exe.bat` | 可选，用 PyInstaller 打成一个 exe |
| `requirements.txt` | 依赖清单 |
| `.venv/` | 已装好依赖的独立环境（删掉也不影响主程序，重跑安装脚本即可） |

> 三个 `.bat` 内部**只用 ASCII 英文**，这是刻意的：批处理被 CMD 按 GBK 代码页解析，
> 文件里若含 UTF-8 中文会被拆成乱码、`rem` 注释行甚至会被当命令执行，导致「双击没反应」。

## 运行方式

1. 双击 `启动.bat`（或 `.venv\Scripts\pythonw.exe clip_chunk_paste.py`）。
2. 托盘出现蓝底三横线图标，弹出「已就绪」提示。
3. 复制长文本 → 在目标输入框里按 **Ctrl+V** → 自动按 20 字一组连续粘贴。
4. 需要长期使用：右键 `启动.bat` → 创建快捷方式 → 放进 `shell:startup` 开机自启。

命令行：

```bat
python clip_chunk_paste.py --debug      :: 带调试输出，日志同时写入 %APPDATA%\ClipChunkPaste\app.log
python clip_chunk_paste.py --selftest   :: 只跑逻辑/剪贴板自检，不启动托盘
```


设置自动保存到 `%APPDATA%\ClipChunkPaste\settings.json`，下次启动沿用。

## 核心逻辑

```
物理 Ctrl+V  →  低级键盘钩子(WH_KEYBOARD_LL) 拦截并吞掉 V 键
             →  后台线程读剪贴板
                 ├ 非文本 / 空 / 被占用 → 补发一次原生 Ctrl+V（行为不变）
                 ├ ≤ 20 字符           → 补发一次原生 Ctrl+V（不折腾剪贴板）
                 └ > 20 字符           → 切片 → 循环[写剪贴板 → SendInput Ctrl+V → 间隔等待]
                                       → 结束后把原始文本还原回剪贴板
```

- 拦截用 `SetWindowsHookEx(WH_KEYBOARD_LL)`，回调里 `return 1` 即吞掉按键；V 的按下和抬起都吞，避免状态错位。
- 钩子回调只做判断，实际工作交给线程，保证回调微秒级返回（否则全系统输入都会卡）。
- 自己注入的按键带 `LLKHF_INJECTED` 标记，钩子里据此放行，不会自激循环。
- 注入用 `SendInput` + 扫描码，每次都是完整的 Ctrl↓ V↓ V↑ Ctrl↑，修饰键状态自平衡。
- 剪贴板走 `OpenClipboard/GetClipboardData/SetClipboardData`（CF_UNICODETEXT），带 12 次重试应对被占用。

## 边界情况

| 情况 | 处理 |
| --- | --- |
| 剪贴板为空 / 空白字符 | 提示一次，退化为普通粘贴 |
| 剪贴板是图片/文件（无文本格式） | 提示一次，退化为普通粘贴 |
| 剪贴板被其他程序锁住 | 重试 12×20ms，仍失败则提示并退化为普通粘贴 |
| 文本 ≤ 20 字符 | 直接原生粘贴，完全不改剪贴板 |
| 末尾不足 20 字符 | 作为最后一组按实际长度发送，不补位、不截断 |
| 文本含换行 | `\r\n`→`\n` 归一化后换行按 1 个字符计，保证与平台字数口径一致 |
| 粘贴过程中重复按 Ctrl+V | 忽略（同一时刻只跑一个任务），不会叠加 |
| 粘贴过程中剪贴板内容 | 会被临时占用为各分组，全部结束后还原原始文本 |
| 中间某组写入剪贴板失败 | 立即中止并提示，`finally` 里仍会尽量还原原始文本 |
| 关闭开关时 | 钩子立即放行，Ctrl+V 回到系统原生行为（钩子常驻但零影响） |
| 重复启动 | 命名互斥体拦截，静默退出，不会出现两个托盘图标 |

## 已知限制

- **权限必须对齐**：目标程序若以管理员身份运行，本工具也需以管理员身份启动，否则钩子收不到按键（UIPI 隔离）。
- 只接管 `Ctrl+V`；`Shift+Insert`、鼠标右键菜单里的「粘贴」不走分组逻辑。`Ctrl+Alt+V`（选择性粘贴）与 `Ctrl+Win+V` 保持原生。
- 长文本粘贴期间若一直死按 Ctrl 不放，可能出现修饰键逻辑状态短暂不同步，松开重按即可恢复。
- 分组位置由字符数硬切，不识别单词/换行边界；emoji 组合序列（ZWJ）有极小概率被从中间切开。
- 前台程序若不是输入框（比如在文件管理器里按 Ctrl+V），分组逻辑仍会执行，效果等同多次粘贴文件——属预期外用法。

## 排查「没反应」

按顺序看这五条，基本能覆盖全部情况：

1. **双击后托盘有没有图标？** Windows 11 默认折叠托盘，点任务栏右下角 `^` 展开，图标是蓝底三横线。
   图标在就说明程序在跑；把图标拖到常显区域即可。
2. **双击后什么都没发生？** 双击 `调试启动.bat`，控制台会显示真实报错（依赖缺失、路径错误等）。
   任何启动异常都会同时写进 `%APPDATA%\ClipChunkPaste\app.log` 并弹窗提示。
3. **有图标但 Ctrl+V 不分段？** 打开 `查看剪贴板分组`，看是否读到文本、算出几组：
   文本 ≤ 20 字符时本来就不会分组（这是设计行为，直接原生粘贴）。
4. **全部正常但目标框没反应？** 目标程序若以管理员身份运行，本工具也必须以管理员身份启动
   （右键 `启动.bat` → 以管理员身份运行），否则低权限进程的键盘钩子收不到按键。
5. **想确认钩子是否生效**：看日志里有没有 `键盘钩子已就绪`；每次成功分组会写
   `开始分组粘贴：N 字符 → M 组`。

`.bat` 文件改动时务必保持纯 ASCII——写入中文会让 CMD 解析错乱，表现为双击后闪一下就没了。
